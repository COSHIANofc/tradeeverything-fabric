# TradeEverything

TradeEverything は Minecraft 26.2 向け Fabric MOD です。新規生成されるバニラの**沼地の小屋**では、構造物が生成する Witch だけを canonical な TradeEverything Villager 商人に置き換えます。小屋本体と Cat の生成はバニラのままで、既に生成済みの小屋は変更しません。

商人は検索可能でサーバー権威の Buy/Sell 画面を開きます。一覧は常に7行を表示し、スクロールできます。検索は前後の空白を除き、大文字・小文字を区別しない部分一致で、ローカライズ名とレジストリ ID を対象にします。右側の詳細欄は、テキストと操作部品で共有するレイアウトにより、長い名前や ID でも重なりません。

## 必要環境と導入

Minecraft 26.2、Java 25、Fabric Loader 0.19.3 以上、Fabric API 0.157.0+26.2 以上の互換版、TradeEverything 0.8.b-dev が、クライアントとサーバーの両方で必要です。Fabric API と `tradeeverything-0.8.b-dev.jar` を両方の `mods` ディレクトリに入れてください。

## 取引

- Buy の支払いにはエメラルドとエメラルドブロックを使えます。エメラルドブロック1個はエメラルド9個分で、まず手持ちのエメラルドを使い、つり銭はエメラルドで返します。
- エンチャント本はバニラエンチャントごとに1つの論理的な一覧項目です。同期された有効範囲からレベルを選択でき、サーバーが保存エンチャントを生成・検証します。
- ポーションは任意の効果の組み合わせではなく、醸造で到達可能な論理的ファミリーです。実在する選択肢と通常／スプラッシュ／残留ポーションを選べます。サーバーが実際のポーション内容を解決して生成します。
- 検索は通常アイテム、エンチャント、ポーションファミリー、実在するポーション ID、容器 ID を対象にします。検索欄にフォーカスしている間は `E` を押すと `e` が入力され、画面は閉じません。`Esc` は通常どおり画面を閉じます。

価格、バリアント選択、インベントリ容量、支払いとアイテム移動はすべてサーバーが検証します。クライアントが ItemStack、PotionContents、NBT、コンポーネントを権威あるデータとして送ることはありません。

## 設定

設定ファイルは `config/config` です。アイテムごとに Buy と Sell を独立して指定できます。

```json
{
  "items": {
    "minecraft:diamond": {
      "enabled": true,
      "buy": {
        "emeralds": 24,
        "output": 1
      },
      "sell": {
        "items": 4,
        "emeralds": 3
      }
    },
    "examplemod:ruby": {
      "enabled": true,
      "buy": {
        "emeralds": 8,
        "output": 1
      },
      "sell": {
        "items": 1,
        "emeralds": 4
      }
    }
  }
}
```

`buy.emeralds` は1回の購入単位の価格、`buy.output` はサーバーが生成する出力数です。`sell.items` と `sell.emeralds` はまとめ売りの比率です。上の例では **4個売るごとにエメラルド3個** となるため、4個・8個は有効で、5個は拒否されます。明示的な `sell` がない場合は、従来の導出式 `SellPricing` が引き続き使われます。

旧形式も互換性のために読み込めます。

```json
{
  "enabled": true,
  "emeralds": 24,
  "output": 1
}
```

旧形式の `emeralds` と `output` は Buy の設定だけを意味します。`buy` が同時にある場合は新形式の `buy` が優先されます。旧設定を読み込んでも、ユーザーの設定ファイルを自動的に書き換えません。

対象のバニラアイテムは従来どおり自動で扱われます。一方、`minecraft` 以外の MOD アイテムは自動列挙されず、有効な明示設定と実際に登録されている ID が必要です。未導入 MOD などで ID が見つからない場合は警告して安全にスキップします。汎用設定で生成する MOD アイテムは通常のデフォルトスタックであり、任意の独自コンポーネントは生成しません。Sell のコンポーネント判定も維持されます。

## 進捗

TradeEverything は4つの進捗を追加します。いずれもサーバーが成功と確定した商人との取引後にのみ付与されます。全アイテム進捗のバニラ canonical universe は固定で1411項目です。対象バニラアイテムは個別に数え、すべてのエンチャント本レベルは1項目、すべてのポーションファミリー／選択肢／容器は1項目、`minecraft` 以外のアイテムは0項目です。中身入りシュルカーボックスを売った場合は中身を記録し、手元に残る箱本体は記録しません。

## コマンド

権限レベル2が必要です。

```text
/tre summon [<x> <y> <z>]
/tre verify
/tre reload
```

`summon` は同一の canonical 商人を作る管理・デバッグ用コマンドです。沼地の小屋での置換確認には使えません。

## 開発

検証済みの最低基準は Minecraft 26.2、Fabric Loader 0.19.3、Fabric API 0.157.0+26.2、Fabric Loom 1.17.2、Gradle 9.7.1、Java 25 です。`./gradlew clean build` で `build/libs/tradeeverything-0.8.b-dev.jar` を生成します。
